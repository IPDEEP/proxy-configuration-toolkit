# 07｜代理连接失败如何排查？

代理连接失败不一定是 IP 地址本身的问题。建议按网络链路逐层检查，并一次只改变一个配置项。

## 1. 核对代理参数

向服务提供方确认：

- Host 或 IP；
- Port；
- 支持的代理协议；
- 认证方式；
- 账号状态和服务限制；
- 是否要求 IP 白名单；
- 是否支持目标客户端。

不要根据端口号猜测协议。

## 2. 检查 TCP 连通性

Windows PowerShell：

```powershell
Test-NetConnection -ComputerName proxy.example.net -Port 10000
```

Linux / macOS：

```bash
nc -vz proxy.example.net 10000
```

TCP 连接成功只表示主机端口接受了 TCP 连接，不代表代理协议协商、认证和目标网站访问都成功。

## 3. 常见故障

### 连接超时

可能涉及端点错误、网络过滤、路由问题、服务不可用或超时设置。先核对 Host、Port，再在获准的网络环境中复测。

### Connection refused

可能是端口没有监听、端点配置错误或服务拒绝连接。核对服务端给出的地址和端口。

### HTTP 407

通常表示代理需要认证或认证未通过。检查用户名、密码、认证格式及账号状态。

### DNS 解析失败

需要区分代理主机域名解析失败，还是目标网站域名解析失败。两者发生在不同阶段。

### TLS 证书错误

检查系统时间、证书链、客户端 TLS 配置和代理端点协议。不要把关闭证书验证作为常规修复方式。

### 目标站点返回 403

代理连接可能已经成功，但目标服务拒绝了请求。应检查目标站点访问政策、请求授权和应用行为。

## 4. 推荐排查顺序

1. 代理主机名解析；
2. TCP 主机与端口连通；
3. 代理协议协商；
4. 代理身份认证；
5. 目标域名解析；
6. 目标服务器连接；
7. TLS 握手；
8. 应用层响应。

不同客户端能够展示的诊断信息不同。

## 5. 提交技术支持时应提供什么？

建议提供操作系统、客户端及版本、代理协议、测试时间、脱敏错误信息和复现步骤。

不要提供明文密码、完整凭据 URL、API Key 或客户个人信息。
