# 09｜代理配置中的凭据与网络安全

代理用户名、密码和访问令牌都属于敏感凭据，应按照 API Key 或数据库密码的安全标准管理。

## 1. 不要提交真实凭据

不要把以下内容写进公开仓库：

- 真实代理用户名和密码；
- API Key 或访问令牌；
- 客户账号或订单信息；
- 内部代理主机名；
- 含凭据的完整代理 URL；
- 未脱敏的日志或截图。

示例统一使用占位符或环境变量。

## 2. 凭据 URL 的风险

类似下面的 URL 包含认证信息：

```text
http://username:password@proxy.example.net:10000
```

根据客户端和系统实现，这类信息可能出现在命令历史、进程参数、调试日志、崩溃报告或截图中。

优先使用安全凭据存储或客户端支持的交互式认证方式。

## 3. URL 特殊字符

用户名或密码中如果包含 `@`、`:`、`/`、`?`、`#` 等保留字符，嵌入 URL 时可能需要进行百分号编码。

编码不等于加密。不要把真实凭据粘贴到不可信的在线编码网站。

## 4. 不要随意关闭 TLS 验证

关闭证书验证会降低连接安全性。出现证书错误时，应先检查证书链、系统时间、信任存储和客户端配置。

## 5. 分享日志前进行脱敏

删除或替换：

- 用户名和密码；
- 完整代理 URL；
- API Key；
- 客户信息；
- 敏感内部主机名和网络地址；
- 其他个人信息。

## 6. 遵守授权和服务规则

仅在有权使用的网络和服务范围内配置代理。遵守所在地法律法规、服务提供方条款及目标网站规则。本项目不提供规避安全控制、欺诈或未经授权访问的操作指导。
